# W11 green contract set: cases that MUST stay byte-exact GREEN.
#
# This is the mirror image of scripts/loud-contracts.txt:
#   loud-contracts.txt  -> every case MUST exit non-zero (a documented rejection)
#   green-contracts.txt -> every case MUST exit zero with ok=True (byte-exact)
#
# They are deliberately SEPARATE files: mixing them would require the gate to
# know which expectation applies to which row, and a mis-filed row would then
# silently invert its own assertion. Two files, two gates, one meaning each.
#
# scripts/green-gate.ps1 reads THIS file, runs scripts/difftest.ps1 -Case <name>
# and requires ok=True (exit 0). Any failure is a hard gate failure.
#
# Format: one case name per line, optional ' #' note. The matching case
# directory lives under tests/cases/<name>/.

# --- W11 P0-D: decimal GroupBy bucket First/Last ---
# Regression anchor for the header/declaration gap fixed in P0-D: the runtime
# DEFINED il2cpp_linq_grouping_first_dec / _last_dec (via the
# IL2CPP_LINQ_GRP_DEC_OPS macro in linq_map.cpp) but linq_map.h never declared
# them, so `grp.First()` / `grp.Last()` over a decimal bucket emitted
# `il2cpp::il2cpp_linq_grouping_first_dec(...)` and the C++ build failed with
# "is not a member of 'il2cpp'".
#
# This case MUST stay ok=True (byte-exact against the net48 oracle). It must
# NEVER become a LOUD reject and must NEVER fail to compile: either outcome
# means the declaration gap came back.
w11probe-linqgrpdec  # GREEN anchor: P0-D decimal GroupBy bucket First/Last must compile and stay ok=True

# --- QCall P2 public surface: Marshal COM slot / visibility markers ---
# The four public QCalls in the P2 gap set (Marshal.GetStartComSlot,
# GetEndComSlot, IsTypeVisibleFromCom, GetTypedObjectForIUnknown) are not
# "missing": each has a MethodMap arm that emits a transpile-time marker,
# and StackFold resolves it to a constant (StackFold.cs ComStartSlotMarker /
# ComEndSlotMarker / ComTypeVisibleMarker). This case pins the answers:
#   IUnknown interfaces start at slot 3; a 2-method interface ends at 4;
#   a derived 5-method interface ends at 5; a non-interface answers -1;
#   [ComVisible(false)] answers False, the default answers True.
#
# Every typeof argument must be a compile-time constant AND a type defined in
# the transpiled assembly -- an external TypeRef (e.g. typeof(int)) is rejected
# by the folder, see docs/audit/qcall-gap-tiers.md section 2.
comslot  # GREEN anchor: Marshal COM slot + visibility fold must stay byte-exact

# ProbeApartmentFail: the REFUSAL half of the Thread apartment surface.
# Net48 throws ThreadStateException from BOTH SetApartmentState and
# (surprisingly) TrySetApartmentState on a started thread, and
# ArgumentOutOfRangeException for a value outside the enum. The 5 lines must
# stay byte-exact. NOTE the scope limit recorded in the case header: the
# STA-ACCEPTING paths are excluded because the net48 oracle cannot format
# exceptions after accepting an STA request on this host (no STA pump).
probe-apartment-fail  # GREEN anchor: apartment refusal channels must stay byte-exact

# ProbeExcBase: a user-defined exception must sit in the exception subtree.
# A user exception's base lives in the BCL, which the loader does not link, so
# the descriptor used to say baseClass = nullptr and is Exception answered
# False. The 13 lines below pin the whole matrix: direct subclass, two-level
# user chain, modelled BCL base (ArgumentException), unmodelled BCL base
# (InvalidOperationException -> falls back to System.Exception), a plain class
# keeping its null root, and the catch path.
probe-excbase  # GREEN anchor: exception base chain must stay byte-exact

# ProbeCatchF6a: a catch handler whose FIRST instruction consumes the entry.
# When the caught object is used only by an s/is expression, Roslyn tests
# the entry directly (brfalse/brtrue) -- and drops the isinst entirely when the
# static type makes the conversion infallible. Without those branch opcodes in
# OpcodeConsumesStack no entry was pushed and the whole method failed to
# transpile ("Stack empty."). The two lines below cover both as-only and
# is-only shapes.
probe-catchf6a  # GREEN anchor: catch entry consumed by a leading branch must fold

# ProbeUserExcMsg: a user-defined exception keeps the message its ctor was given.
# The throw-site carrier is populated from the ctor arguments captured at the
# allocation, but that capture was gated on "is this a BCL exception name",
# which a user type can never satisfy -- every throw carried the placeholder
# text. The three lines below cover a direct subclass, a two-level chain, and a
# non-exception class (the guard against over-broadening the capture).
#
# SCOPE: this pins the INLINE throw/catch path only. Reading the message after
# the exception crossed a method boundary still answers the carrier's own type
# name (the open catch-carrier defect, docs/audit/half-wired-nonp0.md).
probe-userexcmsg  # GREEN anchor: user-exception message must stay byte-exact

# ProbeCatchCarrier: a caught exception must stay an OBJECT across a method
# boundary. The catch variable used to be the exception's type name interned as
# a managed string, so an inline GetType() looked right while a shared
# `Log(Exception ex)` helper answered "System.String" -- the exception's identity
# was gone. The carrier is now a real instance of the thrown type's descriptor,
# synthesised from the throw-time chain when the runtime has no static one, with
# the message captured so Message answers it. The lines cover a runtime-raised
# arithmetic exception, a ThreadStateException (no static descriptor), and a
# user-thrown InvalidOperationException with a ctor message.
probe-catchcarrier  # GREEN anchor: catch carrier must be a real exception object

# ProbeExcMsgCap: an exception's message must survive construction of MANY other
# exceptions. The runtime keeps messages in a fixed 64-entry side table keyed by
# object identity; once it filled, the capture was silently skipped and an
# exception constructed afterwards reported the type-based default text. net48
# has no such limit -- the message lives on the instance. Entries now live in
# chained blocks that never move (the GC roots registered per entry stay valid).
# The lines cover the first exception (message intact), one constructed after
# 128 more (the overflow evidence), and the first again.
probe-excmsgcap  # GREEN anchor: message capture must not have a capacity limit

# ProbeExcParamName: an exception's ParamName belongs to THAT exception. The
# constructed-instance path was already right; the CATCH CARRIER was not -- the
# carrier created its own side-table entry with a null paramName, so the entry
# existed and get_ParamName returned its null instead of falling back to the
# throw-time snapshot. Every `catch (ArgumentException ex) { ex.ParamName }`
# answered "" for a throw that carried a name. The carrier now records the
# ParamName of the throw that raised it. Lines cover: a constructed name read
# before/after an unrelated throw, an exception with no name (must be null, not
# leftover state), two live instances not interfering, and two consecutive
# caught exceptions each answering their own name both inline and through a
# method boundary.
probe-excparamname  # GREEN anchor: ParamName must be per-exception, carrier included

# ProbePInvokeError: Marshal.GetLastPInvokeError / SetLastPInvokeError. These were
# the ONLY two user-callable unwired icalls in the shipped CoreLib 8.0.31
# (docs/audit/corelib-p0-shipped-recut.md), and an unwired one emitted an
# undefined symbol at every call site. The setter writes the per-thread CAPTURED
# slot rather than the OS error (SetLastWin32Error writes that), because net8's
# getter reads the captured value -- writing the OS error would set a value the
# getter never sees. Lines cover set/read round-trip, replacement, zero as a
# legal value, the negative range, and GetLastWin32Error reading the same slot.
probe-pinvoke-error  # GREEN anchor: PInvoke error code round-trips through both members

# ProbeMarshalHelpers: the public Marshal surface whose native helpers
# (SizeOfHelper / OffsetOfHelper / PtrToStructureHelper) are among the 68
# reachable-but-internal gaps -- these calls work, which is what proves those
# gaps are not load-bearing for user code. Restricted to the registered struct
# family: SizeOf/OffsetOf on a user struct is a documented LOUD boundary, and
# Marshal.GetExceptionForHR has no runtime HR->Exception conversion.
probe-marshal-helpers  # GREEN anchor: Marshal.SizeOf/PtrToStructure over the registered struct family
# ProbeInterlockedWidths: signed 32/64 Interlocked already worked; these cover the
# unsigned widths (UInt32/UInt64) and the .NET 9 And/Or pair. All of them are
# BODILESS public wrappers -- no IL body -- so an unmapped arm emitted an
# undefined C++ symbol and the program failed to COMPILE, not merely misbehaved.
# Requires net9.0: Interlocked.And/Or do not exist in net8.
probe-interlocked-widths  # GREEN anchor: unsigned Interlocked widths + And/Or round-trip

# CorelibP0: the P0 CoreLib surface (GC / RuntimeHelpers / Interlocked / Thread /
# Math) end to end. Registered after it caught a regression no other case did:
# the phantom guard added in 2475f4a2 rejected `new Action(...)` because
# IsExternalBclOwner exempted `System.Action`1` but not the bare `System.Action`.
# Every probe run at the time happened not to construct a non-generic delegate,
# and this case was in no contract file, so nothing ran it for four rounds.
# A guard that exempts the delegate families must be exercised by a case that
# uses them.
corelibp0  # GREEN anchor: P0 CoreLib surface must transpile and stay byte-exact

# DelegateBclInvoke: every BCL delegate family, without a name list.
# Construction is decided by the ctor signature (Void .ctor(Object, native int))
# and invocation by the tracked receiver type. Covers a System.dll delegate
# (PropertyChangedEventHandler), a mscorlib reflection callback (MemberFilter),
# a generic delegate (Func<int,int>), and the CROSS-METHOD shape that regressed
# corelibp0 -- a delegate constructed in one method and invoked in another,
# which a per-fold type set cannot see. Delegate.Combine/Remove are exercised
# through the Delegate-typed result without a castclass back to Action (castclass
# to a BCL delegate is a separate, pre-existing gap).
delegate-bcl-invoke  # GREEN anchor: BCL delegate construction + Invoke across method boundaries

# DelegateAbiSignatures: the delegate invocation ABI across the common signature
# families. Construction is signature-based and Invoke is receiver-typed, but
# neither proves the CALL is emitted with the right width: a string/long/double
# result routed through the int32 helper would compile and silently truncate.
# Covers void(), int(int), string(string), long(long), double(double),
# bool(int,int), void(object), int() -- the eight shapes a user program hits
# first. The string/long/double arms emit a per-signature
# il2cpp_delegate_multicast_<hash>; int/void use the shared icall helpers.
delegate-abi-signatures  # GREEN anchor: delegate invocation ABI across signature families

# DelegateByrefParams: ref/out delegate parameters. These were REJECTED outright
# (delegate Invoke with a byref (0x10) parameter/return is not supported), so
# every delegate void F(ref int) failed to transpile -- single-cast included,
# not just multicast. The fold already lowers ldloca to LocAddrExpr, which emits
# (&name), so the leaf ABI is <elem>* and the generated per-signature
# multicast helper carries it as a plain C++ parameter. Covers ref, out, and two
# ref params (the swap shape).
delegate-byref-params  # GREEN anchor: ref/out delegate parameters must transpile and round-trip

# DelegateStructSignatures: a delegate whose parameter or return is a VALUE TYPE.
# The multicast helper names the SAME C++ struct the leaf method declares
# (ConsumeDelegateSigFull maps 0x11 through TypeCppName), so the platform
# aggregate ABI applies on both sides with no manual expansion: on x64 a 16-byte
# aggregate rides a hidden by-ref slot and the return comes back through sret.
# If that mapping ever degrades to a bare int32/int64 pair the copy tears
# silently -- the program still compiles and still prints a number, just the
# wrong one. Covers a struct return (Pt F(int,int)), a struct parameter
# (int G(Pt)), and a plain string return as the no-struct control.
delegate-struct-signatures  # GREEN anchor: value-type delegate params/returns must keep the aggregate ABI

# Array.CreateInstance(Type, ...) -- the element type arrives as the simplified
# Type model (a full-name string), so the runtime resolves it to a class descriptor
# and takes the element size from there. Covers the 1-D (Type,int) form plus
# Length/GetType().Name/SetValue/GetValue on the result.
probe-arraycreate  # GREEN anchor: Array.CreateInstance must allocate a sized array from a Type value
# Array.Clone() -- a shallow copy: a new array of the same shape with the
# element payload copied verbatim (reference elements copy the SLOTS). Covers
# int[]/string[] clones, clone independence, and the shallow reference contract.
probe-arrayclone  # GREEN anchor: Array.Clone must copy the payload into a new array
# The castclass/isinst path must SYNTHESIZE the element-array class, not just
# query the registry: a synthesized class is registered on first allocation, so
# (long[])x used to fail whenever no long[] existed yet. Covers i8/f8/ref/i4/i2/u1
# plus a failing cast that must throw InvalidCastException.
probe-arraycast  # GREEN anchor: array casts resolve the element class on demand
# A generated (Array)o / o as Array names System_Array_class directly. It used to
# be an undefined symbol (the case failed to COMPILE, not at run time), because no
# System.Array descriptor existed. Every array class now converges on it:
#   int32[]/value-element[] -> System.Array -> System.Object
#   object[]/ref-element[]  -> object[] -> System.Array -> System.Object
# Covers cast, as, a failing cast, GetValue through the base type, and Clone.
probe-arraybase  # GREEN anchor: System.Array is a real descriptor and the array base chain reaches it

# A multidim ARRAY (0x14) TypeSpec cast target used to throw at TRANSPILE time:
#   TypeSpec signature byte 0x14 not GenericInst(0x15) in M5
# The 0x14 arm now resolves a RANK-CARRYING array class, because net48 keeps
# int[] and int[,] as distinct types: the conformance test is an identity
# comparison, so the rank must be part of the descriptor name ("[System.Int32,2").
# Covers (int[,])x, as, a failing cast, element access, and the rank-exclusion
# assertions in BOTH directions (int[] must reject int[,] and vice versa).
probe-arraymd  # GREEN anchor: multidim casts resolve a rank-carrying array class

# Array.CreateInstance(Type, int[], int[]) used to DROP the lowerBounds argument
# (the mapping passed 2 args for a 3-arg call), so GetLowerBound always answered
# 0 and a non-zero lower bound was silently lost. net48 keeps the lower bound in
# the array header: lengths {3} + lowerBounds {5} means valid indices 5..7.
# Covers a non-zero bound, indexing from it, the zero-based case, a 2-D array
# with a different bound per dimension, an out-of-range index below the bound,
# and a NEGATIVE lower bound.
probe-arraylower  # GREEN anchor: CreateInstance lower bounds are modelled and applied once

# System.Array's generic search/transform surface plus three IList flags. The
# search family (Empty/Exists/Find/FindIndex/FindLast/FindAll/TrueForAll/
# Resize/ForEach) was already wired; GetLongLength(int) and the three flags
# (IsFixedSize TRUE, IsReadOnly FALSE, IsSynchronized FALSE) were not, and
# GetLongLength failed to transpile with "not wired in M5".
probe-arrayapi  # GREEN anchor: Array search surface + GetLongLength + IList flags

# Array.get_SyncRoot: net48 answers the array ITSELF as the synchronization
# object, so the result must be the receiver unchanged and stable across
# calls. The mapping arm needs ReturnsRef (the 4th I() flag) or the result temp
# is declared int32_t and the generated C++ rejects the pointer assignment.
probe-arraysync  # GREEN anchor: SyncRoot is the array itself, stable, null throws

# Array.GetEnumerator: the non-generic IEnumerator over the array. The
# enumerator object is the shared Il2CppArrayEnumerator, so MoveNext/Reset ride
# the existing il2cpp_sortedlist_enumerator_* icalls. The element READ must box
# a value element: il2cpp_ienum_get_current_obj routes the SortedList enumerator
# class through ArrayEnumRef (which boxes by element kind), NOT through the
# reference-only il2cpp_sortedlist_enumerator_get_current -- that read
# dereferences the int payload as a pointer and crashes.
probe-arrayenum  # GREEN anchor: array enumerator boxes value elements on the object carrier

# Array.AsReadOnly<T>: net48 returns a ReadOnlyCollection<T> that is a VIEW over
# the source array (writes through the array are visible, and the collection
# rejects mutation by construction). This needed the whole ReadOnlyCollection<T>
# runtime (readonlycollection.h/.cpp) plus the AsReadOnly arm that hands the
# array to it. Covers Count, the int indexer, enumeration, Contains, IndexOf,
# CopyTo, an EMPTY array, and a reference-element instantiation -- the int32 and
# the object element families are separate accessor pairs, so a case that only
# exercises one cannot see the other's wiring.
probe-arrayreadonly  # GREEN anchor: Array.AsReadOnly returns a live ReadOnlyCollection<T> view

# p-nb4-gc: the Volatile family over EVERY width net48 declares, plus the two
# GC notification icalls. net48's Thread.VolatileRead/VolatileWrite have 13
# overloads each and System.Threading.Volatile has 14; only int and long were
# wired, so the other 24 failed to transpile with "no BCL mapping in M5". The
# probe writes a sentinel through one overload and reads it back through the
# other, so a wrong-width dispatch cannot hide behind a plausible number. The
# slot-width contract is load-bearing: byte/sbyte/bool share i1, char/short/
# ushort share i2, int/uint/single share i4, long/ulong/double share i8,
# IntPtr -> ip, UIntPtr -> up, every reference -> obj.
p-nb4-gc  # GREEN anchor: Volatile fence atomics over every net48 width

# probe-charstr: System.Char's (string, int) overload family. net48 declares a
# SECOND set of the same predicates that index into a string instead of taking
# one char -- char.IsDigit(s, i), char.IsLetter(s, i), char.GetUnicodeCategory
# (s, i), and so on. Only the single-char overloads were wired, so every call in
# this family failed to transpile with "no BCL mapping in M5" (a whole-method
# loss, since the BCL body is not in the input assembly). The probe prints the
# predicate answer for a mixed-classification literal plus the enum NUMERIC
# values (cat1=8 for a digit, cat0=1 for a lowercase letter), so a wrong index,
# a missing bound check, or a category mapping that returns the wrong ordinal is
# visible.
probe-charstr  # GREEN anchor: char (string, int) overloads incl. UnicodeCategory ordinals

# probe-encodingprops: System.Text.Encoding's metadata surface. The singletons
# already worked (GetBytes/GetString round-trip); the code-page getters, the name
# getters, the browser/mail-news flags, Clone/Equals/GetHashCode, GetMaxByteCount/
# GetMaxCharCount, GetEncoding(int|string) and UTF32/UTF7 were all unmapped, and
# because Encoding's body is not in the input assembly each one was a
# whole-method loss. Encoding.Default is the HOST ANSI code page (GetACP), so it
# tracks the machine exactly as net48 does rather than a hardcoded constant. The
# concrete encodings also inherit from Encoding now -- without that base chain a
# (Encoding)utf8Instance castclass fails.
probe-encodingprops  # GREEN anchor: Encoding code-page/name/identity surface
