# W11 F1-b controlled active LOUD contract set.
#
# scripts/loud-gate.ps1 reads THIS file (not sweep-exclude.txt's note text) as
# its protection object. It is a fixed, always-non-empty sentinel set: every
# case here MUST exit non-zero from scripts/difftest.ps1 AND emit documented
# exception evidence. Format: one case name per line, optional ' #' note.
# The matching case directory lives under tests/cases/<name>/.
#
# The case is ALSO registered in scripts/sweep-exclude.txt with a "LOUD
# contract" note so (a) the byte-exact full-pool sweep does not count it as a
# permanent FAIL, and (b) difftest.ps1 does NOT take its SKIP early-return.
zz-loud-sentinel  # LOUD contract: W11 F1-b fixed sentinel, must throw NotSupportedException

# --- W11 P0-A: Console DEVICE surface regression anchors ---
# These four probes are the ONLY coverage of the Console device surface
# (Clear / Beep / Title / colors / cursor / window+buffer metrics): a scan of the
# 1251 pre-existing cases found zero references to those members. They are
# registered here (NOT in sweep-exclude.txt) because a LOUD contract must be
# EXECUTED and verified to still throw, not silenced.
#
# Contract after W11 P0-A: MethodMap.Console.cs maps all 21 device members to
# ConsoleDeviceNotImplemented(...), which throws
# "LOUD whitelist (console device surface not implemented)". difftest therefore
# exits non-zero with "not transpiled" + "Unhandled managed exception" and the
# C++ build has ZERO errors (no undefined icall_console_* symbol).
#
# They are also the acceptance anchors for a future (a) REAL implementation:
# when console_device.cpp lands, these four must flip from LOUD-reject to
# byte-exact difftest PASS, and loud-gate must then be updated (or these rows
# removed) in the same change.
w11probe-console   # LOUD contract: W11 P0-A Console device surface (Clear/Beep) must reject, never emit il2cpp::runtime::icall_console_*
w11probe-clear     # LOUD contract: W11 P0-A Console.Clear() must reject, never emit icall_console_clear
w11probe-setters   # LOUD contract: W11 P0-A Console setters (ForegroundColor/BackgroundColor/Title/CursorLeft/CursorTop/CursorVisible) must reject
w11probe-getters   # LOUD contract: W11 P0-A Console getters (Title/colors/cursor/window+buffer) + SetCursorPosition/ResetColor/Beep(f,d) must reject


# --- Phantom BCL call guard: the emitter must reject, not emit an undefined symbol ---
# Marshal.GetExceptionForHR has no HR->Exception conversion in the runtime, and its
# owner (System.Runtime.InteropServices.Marshal) is an EXTERNAL BCL type -- the input
# assembly never defines it. Resolving the call yields a PHANTOM: a generated name
# (System_Runtime_InteropServices_Marshal_GetExceptionForHR_<hash>) that no translation
# unit defines, so the failure used to surface as a cmake "use of undeclared
# identifier" far from the cause.
#
# TWO independent guards must reject it, and this case pins both:
#   1. MethodMap.Marshal.cs allow-lists the name -> "LOUD whitelist (marshal member
#      not wired)".
#   2. The emitter's phantom guard (CodeGenerator: the `resolved2` expression arm,
#      the `resolvedStmt` statement arm, and EmitFunctionName) throws for any
#      IsFictionalBclFallback result -- so even with the allow-list entry removed the
#      transpile still fails loudly.
#
# The probe calls GetExceptionForHR in EXPRESSION position and ThrowExceptionForHR in
# STATEMENT position so both emitter arms are exercised. It deliberately does NOT call
# ex.GetType(): that member is itself a fold-time phantom reject and would mask which
# guard fired.
loud-marshal-hr  # LOUD contract: phantom BCL calls must be rejected at the emitter, never emitted as undefined symbols

# --- Phantom guard, DELEGATE half ---
# A phantom name used as a FUNCTION POINTER (&Name) is worse than a call: the
# transpile used to EXIT 0 and the undefined symbol only surfaced at cmake.
# CodeGenerator.MethodCppNameFromToken now rejects it. Separate from
# loud-marshal-hr because the two take different emitter paths.
loud-marshal-hr-delegate  # LOUD contract: a delegate bound to an unmapped BCL method must reject, never emit &<phantom>
