# 生成代码风格规范（Generated Code Style Specification）

日期：2026-08-02
状态：生效（spec 4.4 引用）
参考风格来源：D:\dd\openppp2（高度缩进 + 列对齐工程风格）

## 目标

il2cppc 转译器生成的 C++ 代码必须达到**手写高质量工程代码**水准：可读、可审计、确定性、规范统一。生成代码是项目产品的一部分（用户会读它、审它、改它），不是一次性垃圾输出。

## 1. 缩进与对齐（openppp2 风格）

- **4 空格缩进**，禁止 tab；嵌套（namespace/class/函数体/if/for/switch）每层 +4
- **行尾注释列对齐**：`code;  // comment` —— 注释统一右对齐到第 100 列；代码短于 100 列时补齐空格；超长代码行则 `code; // comment`（单空格）
- **声明区列对齐**：同一块内连续声明，类型/名称/注释按列对齐（openppp2 的 `type  name;  // desc` 风格）
- **代码对齐**：逻辑配对的行（如连续赋值、连续返回）对齐到同一列

## 2. 命名规范（生成侧）

- 函数名：`{Ns}_{Type}_{Method}_{SigHash}`（确定性编码，FNV-1a 64 后缀，spec 4.4 定义）
- 标识符 sanitize 统一规则：`. + / ` < > , [ ]` 等非标识符字符 → `_`；连续 `_` 合并；首字符为数字则前缀 `_`
- 局部变量：IL 局部变量 → `loc{N}`；临时变量 → `t{N}`；参数 → `arg{N}`（与 IL 槽号对应，可审计）
- 静态字段：`{TypeCppName}_sf_{FieldName}`
- 标签：`L_{ILOffset}`（与 IL 偏移对应，可审计）
- 禁止生成 `_` 前缀的双下划线（保留字冲突）；禁止生成 C++ 关键字同名标识符（sanitize 时检查）

## 3. 注释规范（生成侧）

- **文件头块**：
```
//------------------------------------------------------------------------------
// generated by il2cppc <version>
// source assembly: <assembly-path 相对路径>
// DO NOT EDIT - regenerate with il2cppc
//------------------------------------------------------------------------------
```
（无绝对路径、无时间戳 —— 确定性要求，spec 11.8）
- **函数头注释**：每个生成函数前必须标注托管来源：
```
//------------------------------------------------------------------------------
// IL method: System.Int32 Calc.Program::Add(System.Int32,System.Int32)
// IL offset: 0x00000010 (assembly:calc.dll, token:0x06000004)
//------------------------------------------------------------------------------
```
- **语句级注释**：复杂表达式/分支生成处，从 IL 语义推导加说明（如 `// ldarg.0` 对应说明）
- **节分隔线**：`//------------------` 分隔函数/声明区
- **include 顺序**：对应头 → 项目内部（`"..."`）→ 系统（`<...>`），组间空行

## 4. 表达式生成规范

- **宁可多括号**：二元表达式一律 `(l op r)` 带括号，禁止依赖 C++ 优先级（C9/G3 安全优先）
- 整数常量：int32 → 十进制；int64 → 十进制 + `LL` 后缀；负常量直接输出（不依赖一元负号结合）
- 字符串常量：C 转义输出（`\n`/`\"`/`\\`/非打印字符 `\xNN`）
- 布尔：`0`/`1`（int32 语义，对齐 IL）

## 5. 语句生成规范

- 每语句独立一行；`{` 换行独占（Allman 风格，与 openppp2 一致）
- `if (cond) { ... } else { ... }` 嵌套缩进
- goto 标签独立一行，左对齐（同函数体内标签不缩进）
- 生成代码禁用手写技巧（三元嵌套、逗号表达式、宏）—— 简单直白优先

## 6. 确定性（可复现构建）

- 同一输入程序集 + 同一 il2cppc 版本 → 生成字节完全一致的输出
- 禁止：时间戳、绝对路径、随机顺序（字典序稳定遍历元数据）、编译器相关文本
- 哈希/签名必须跨进程稳定（FNV-1a，禁用 string.GetHashCode）

## 7. 质量门（CI 强制）

- **C++ 标准 = C++17 仅**：运行时与生成代码全部 C++17，禁止 C++20+ 特性（concepts/ranges/coroutines/modules/`<=>`/designated initializers 等一律禁用）
- 生成代码在 MSVC `/W4 /Wall(选定项)` 与 MinGW `-Wall -Wextra` 下**零警告**
- 生成代码通过两编译器零错误编译（C0）
- 生成文件按 4.4.1 拆分策略（大小上限内）—— 风格规范不因文件变大而妥协

## 8. 审查要求

- 生成代码纳入 code review 范围：抽查生成产物是否符合本规范
- 转译器本身代码风格：同样遵循本规范缩进/对齐精神（C# 侧 4 空格 + 列对齐注释）
