# ILC Naming Audit & Layered Rename Plan

> Status: **PLAN ONLY — no rename has been executed.** Audit snapshot: 2026-08-03.
> Goal: eliminate the historical `il2cpp` naming residue so the project name is
> uniformly **ILC (ilc)** across directories, namespaces, project files, type
> names, macros, C API prefixes, and documentation.

## 1. Terminology

| Residual form | Meaning | Example |
|---|---|---|
| `il2cppc` | historical project/assembly name of the transpiler | `src/il2cppc/`, `il2cppc.csproj`, `il2cppc.dll` |
| `Il2Cpp.*` | C# namespace of the transpiler | `Il2Cpp.Transpiler.Emit` |
| `Il2Cpp*` | runtime C++ type names | `Il2CppObject`, `Il2CppClass`, `Il2CppString` |
| `il2cpp_*` | C API / runtime function prefix | `il2cpp_string_new`, `il2cpp_runtime_init` |
| `il2cpp` | C++ namespace of the runtime + header file prefix | `namespace il2cpp`, `il2cpp_object.h` |
| `IL2CPP_*` | macros | `IL2CPP_EXPORT`, `IL2CPP_NOINLINE`, `IL2CPP_C_API` |
| `il2cpp_runtime / il2cpp_gen / il2cpp_gen_exe` | CMake target names | emitted `project(il2cpp_gen CXX)` |

Note: `Il2CppException` / `Il2CppValue` do **not** exist — exceptions are
`il2cpp::DotNetException` (27 hits). This does not affect the plan.

## 3. Layer-by-layer plan

### Layer 1 — Docs + comments (zero risk, do first)

| Item | Count |
|---|---|
| docs `.md` occurrences | 1,618 in 39 files |
| `README.md` / tests READMEs | 28 in 4 files |
| C# comments mentioning `il2cppc` / `Il2CppClass` / `il2cpp_*` | transpiler cs comments (subset of 1,057; e.g. CodeGenerator.cs:87,106,1288,2294,2343; TypeEmitter.cs:33,150; MethodMap.*.cs headers; Model/FieldDef.cs:10; TypeDef.cs:10,78,84) |
| emitted comment `// generated by il2cppc` | CodeGenerator.cs:28,133 (behavior-safe but belongs to L5 textually; may be done here) |

- **Target**: replace `il2cppc` → `ilcc` / `ilc`, `Il2Cpp*` → `Ilc*` in prose and
  comments only (no identifiers touched yet — comments referring to identifiers
  may be deferred to the layer that renames those identifiers to keep the
  comments truthful; prefer deferring identifier-bearing comments).
- **Verification**: `rg -i il2cpp docs/` (excluding the 1 Unity mention and
  archival docs if kept) → 0. `dotnet build` unaffected (comments only).
- **Risk**: none (no compiled tokens). Watch: Chinese comments with embedded
  `il2cpp` text are replaced the same way.
- **Execution batch**: standalone, any agent, anytime. Also fold in `scripts/`
  comments if any.

## 4. Recommended execution order & batching

```
L1  docs+comments          → grep verify (docs il2cpp → 0)
L2  C# namespace           → dotnet build + dotnet test      (parallel with L3)
L3  IL2CPP_* → ILC_*       → full CI, 3 compilers            (parallel with L2)
L4A Il2Cpp* → Ilc* + ns    → full CI, 3 compilers
L4B il2cpp_* → ilc_* + .h  → full CI, 3 compilers + run-capi
     file renames + cmake targets
L5  src/il2cppc → src/ilcc → fresh-clone full CI, only after ALL agents done
```

**Recommendation for L4: two batches (4A then 4B), not one.**
Rationale: although the entire L4 is a purely mechanical, semantics-preserving
identifier rename, the blast radius is ~15,000 occurrences across 326 files.
Splitting by identifier *class* (types+namespace first, functions+filenames
second) gives two independently verifiable halves — if a build breaks, the
failure is isolated to one half and the diff is reviewable. Each half gets the
full 3-compiler CI, so the only cost is running the chain twice; the debugging
cost of a single 15k-occurrence rename failing late is higher. If CI time is
the dominant constraint, a single L4 pass with the §5 replacement rules is
acceptable — never split by *file* (headers and cpp are mutually dependent).

## 5. Replacement safety rules (apply to all layers)

1. **Longest-first, word-boundary regexes.** `Il2CppStringBuilder` → `IlcStringBuilder`
   before `Il2CppString` → `IlcString` before bare `Il2Cpp` → `Ilc`. Never a
   naked global `Il2Cpp`→`Ilc` replace (would corrupt the namespace string and
   intermediate types).
2. **Identifier-first, prose-later.** Rename identifiers in L2/L4 first; L1
   comment/doc text that *names* identifiers is corrected in the same layer
   that renames them, so docs never name a non-existent symbol.
3. **Never hand-edit `gen/`** (gitignored, regenerated by run-tests.ps1).
   Verification always regenerates from the transpiler.
4. **Verify with fresh regenerate** after every batch: unit + runtime +
   e2e on msvc, mingw, wsl (run-tests.ps1:2) + run-capi.ps1 — 3 compilers.
5. **No ABI compatibility required** (no released binary contract): C API
   symbol renames are fine as long as run-capi passes.
6. **Backup before edit** per project rule (`.opencode/backups/`).

   replace like the rest (mechanical, zero risk), or (b) leave as records and
   add a one-line header note "naming predates ILC rename". Recommend (a) for
   uniformity, since the iron rule covers docs; (b) is defensible for
   auditability. **User decision.**
2. **`docs/superpowers/specs/2026-08-02-il2cpp-design.md`** is the project's

3. **Header file naming**: `il2cpp_*.h` → `ilc_*.h` (uniform, mechanical) vs.
   continuing the existing domain-name migration (`attribute.h`, `guid.h`…,
   31 already renamed). **Recommendation: `ilc_*` prefix for L4B uniformity;
   domain-name migration is a separate style task.**
4. **L5 timing**: requires all parallel agents to have stopped editing
   `src/il2cppc/` — coordinate via the project owner before starting L5.
