# 性能优化路线图（分阶段）

> 依据：docs/REQUIREMENTS.md 铁律 2e（生成代码性能 >= 官方 JIT）、铁律 2f-2
> （表达式最大化折叠、禁伪栈模拟）、铁律 2j（性能最高优先 + 属性折叠）。
> 每阶段可独立交付、可验证（以双跑一致 + 基准数据为验收，不空谈）。
>
> 关联：属性折叠见 docs/architecture/属性折叠设计.md；
> JIT 预留见 docs/architecture/jit-预留.md；总里程碑见 docs/architecture/路线图.md。

---

## 阶段 1：转译器基础优化（编译期，零运行时成本）

目标：生成代码的"优化器友好度"最大化——让 MSVC/MinGW/GCC 的 -O2
（常量传播/CSE/寄存器分配/内联）能全力工作（铁律 2f-2 检查基准）。

| 项 | 现状 | 目标/做法 | 验证 |
|---|---|---|---|
| 属性折叠 | 无（get_/set_ 编译为函数） | 见 属性折叠设计.md——调用点折叠为字段访问，accessor 不发射函数 | 反汇编无 call；双跑一致 |
| 常量折叠 | 已有 int32 回绕折叠（`TryFoldInt32`，CodeGenerator.cs，unchecked 语义 + 符号扩展） | 扩展覆盖面：int64 常量运算、字符串常量拼接（相邻 ldstr/运算）、枚举常量 | 单测 + 生成代码抽查 |
| temp 最小化 | 已有：可达性分析 + 死块消除（CodeGenerator.cs:215-264）；call/join/快照三来源 temp（铁律 2e） | **只写不读 temp 消除**（M2 时 YAGNI 未做，M5 体量下必须）：temp 只被赋值未被读取 → 不声明/不发射 | -Wall -Wextra /W4 零警告 + 生成代码审查 |
| 表达式深度 | 栈折叠已最大化（铁律 2f-2）；join 点被迫 spill 是语义要求 | 分支条件归一化（`Ceq(e,0)` 反写为 `e == 0` 剥多余括号，EmitCondition 已有） | 生成代码抽查 |
| 字段访问发射 | FieldExpr 直接 `obj->f`（CodeGenerator） | 保持零间接层；引用字段 cast 不产生多余拷贝 | 反汇编抽查 |
| 栈帧根协议 | WrapFrameRoots 每方法无条件包裹（CodeGenerator.cs:176） | **refLocals 为空时跳过包裹**（帧记录零开销——多数纯值方法无引用局部） | gcstress 回归 + 基准 |

阶段 1 验收：现有 e2e 全绿 + 新 fixture（属性密集/循环密集）双跑一致；
反汇编抽查热路径无多余调用/临时变量。

## 阶段 2：运行时优化（共享核心，AOT 与 JIT 同受益）

| 项 | 现状 | 目标/做法 | 验证 |
|---|---|---|---|
| 分配器池化 | 分代 GC：Gen0/1/2 bump + LOH + 写屏障卡表（M3，gc.cpp） | **线程本地分配缓冲（TLAB 风格）**：Gen0 bump 指针 per-thread，降低分配锁竞争；大对象直入 LOH | 多线程分配基准；gcstress 稳定 |
| icall 内联 | icall 是普通跨 TU 函数调用（il2cpp_runtime.h:104-134） | 简单 icall（如 `icall_environment_get_newline`、字符串长度）提供头文件内联实现（IL2CPP_FORCE_INLINE 或 constexpr 路径）；或生成代码直读字段 | 反汇编无 call；双跑一致 |
| 字符串缓存 | 每个 ldstr 运行时 `il2cpp_string_new_from_cs` 新分配（string.cpp） | **编译期字符串池**：entry.cpp 一次性构造全部字符串字面量（静态引用表），ldstr 折叠为表索引读取（零运行时构造）；interning 表运行时共享（JIT 阶段复用） | 字符串密集基准；双跑一致 |
| null 检查 | `il2cpp_null_check` 每次解引用一次调用（il2cpp_runtime.h:68） | 检查内联化：生成代码发射 `if (!obj) throw_…` 直接形态（宏/内联助手 + `__builtin_expect`），编译器可优化掉安全冗余检查 | 反汇编抽查；异常用例回归 |
| 帧记录 | framestack push/pop 每方法（三合一机制，铁律） | 无引用局部方法零帧记录（与阶段 1 的 WrapFrameRoots 跳过配套）；栈根区间批量注册 | gcstress + StackTrace 用例回归 |
| 接口分派 | 线性扫描（metadata.cpp:116-154 注释明示 M2 线性、M3 哈希） | 接口映射哈希化（iface → entry 哈希，M3 已注释的优化项） | 接口密集基准 |
| C API 边界 | 每次导出调用 try/catch（api.cpp:107） | 保持（异常防护是铁律）；避免热点导出路径额外开销（字符串比较 → 方法 id 预解析） | capi 测试回归 |

阶段 2 验收：基准工具就绪（阶段 4 先行搭建最小 bench 骨架）后逐项
对比 AOT vs .NET 4.8 官方 JIT；每项双跑一致回归。

## 阶段 3：代码生成优化（生成器算法级）

| 项 | 说明 | 做法 |
|---|---|---|
| 公共子表达式复用 | 生成器与 C++ 编译器双重 CSE：生成器不做多余 temp，把机会留给 -O2（铁律 2f-2）；但**跨语句的重复子表达式**（编译器受内存别名限制时）可生成器侧折叠 | 先实测（反汇编找重复计算），命中再实现——避免过度工程 |
| 死代码消除（生成器） | 已做：常量分支定死 + 死块消除 + 死 label 消除（CodeGenerator.cs:215-264） | 扩展：只写不读 temp（阶段 1）、不可达赋值链清理 |
| 内联策略研究 | **禁内联是 StackTrace/帧记录铁律**（memory.md 记录）；属性折叠是合法替代 | 研究项：`[MethodImpl(MethodImplOptions.AggressiveInlining)]` 属性 → 编译期选择发射内联体（函数内联但保持帧记录序言？——需证明帧根/StackTrace 语义不破坏，先文档后实现） |
| 泛型共享代码 | 引用类型实参共享单代码（M3 机制） | 保持；值类型特化限量（每基元 1 份） |
| 调用约定 | 现有 ABI（this=arg0） | 研究：寄存器传递优化参数数量 >N 时栈传递开销（与 C API/导出 ABI 对齐，属研究项） |
| 布局优化 | 字段按声明序布局（TypeEmitter slot 网格） | 研究：字段重排（按引用/值分组，GC 扫描局部性 + 对齐）；**风险：破坏反射字段顺序语义——需用户裁决，默认保持声明序** |

阶段 3 验收：每项以"基准对比 + 反汇编证据"证明增益，无证据不并入。

## 阶段 4：基准体系（防回归，长期保障）

目标：把"性能 >= 官方 JIT"（铁律 2e）从口号变成可度量的 CI 门。

| 组件 | 内容 |
|---|---|
| tests/bench/ 目录 | 微基准套件（与官方 JIT 对比）：整数运算、循环、对象分配/回收、字段访问、属性访问（折叠生效验证）、虚调用、接口调用、字符串操作、数组、装箱、委托调用、P/Invoke 边界 |
| 双跑对比 | 同一机器同一输入：AOT 产物 vs .NET Framework 4.8 官方 JIT 运行同源 C# 程序（net48 参考，与 run-tests.ps1 双跑同源）；记录耗时/分配量 |
| 反汇编审查 | dumpbin /objdump 对热点函数断言形态（无意外 call、无 temp 泛滥、属性折叠生效）——与 属性折叠设计.md §5.2 联动 |
| 性能回归 CI | 基线入库（首次测量定基线）；CI 增性能步：对比波动 > 阈值（如 10%）→ 失败报警；回退即失败（铁律 2e 原文"回退即失败"） |
| 全程序优化 | 链接期 LTO/IPO（MSVC /GL+/LTCG、MinGW -flto）：跨 TU 内联/常量传播（与三编译器零警告门兼容性验证） |
| 分析工具 | 开发期：Windows Performance Analyzer / VTune / perf（WSL）；性能缺陷修复后反汇编+基准双证据入库 |

阶段 4 前置依赖：M5.5 裁剪分级验证后 BCL 形态稳定，基准才有代表性；
M6 测试套件全绿后基准门才可靠（避免性能噪声掩盖正确性失败）。

## 阶段依赖与排期建议

```
阶段 1（转译器基础，M5 并行域，随属性折叠一同落地）  ← 依赖：属性折叠设计落地
   ↓
阶段 2（运行时优化，M5-M6）         ← 依赖：阶段 4 的最小 bench 骨架先行搭建
   ↓
阶段 3（生成代码算法级，M6 后）     ← 依赖：基准体系可度量增益
   ↓
阶段 4（基准体系，M6 起长期运行）   ← 依赖：测试套件全绿 + BCL 形态稳定
```

原则（铁律 2e 效率约束）：**每处设计都问"这个开销官方 JIT 是否也要付？
如果不付，我们为什么付？"**——优化只消除我们独有的开销（调用点间接层、
temp 泛滥、帧记录冗余、icall 跨边界），不追求与 C++ 手写代码争高下。
