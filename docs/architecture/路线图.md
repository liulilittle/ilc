# 总路线图：从当前 M4 到"用户动态编程"

> 依据：docs/REQUIREMENTS.md 铁律 2j（JIT/动态编程 = 暂定计划，先推进 AOT）、
> 铁律 3（里程碑链 M1-M8）、铁律 13（iOS 无动态代码生成，M7 解释器兜底）。
> 本文档把"未来支持用户运行时动态写代码执行"分解为四个递进阶段，
> 每阶段有明确交付物与验收标准；当前只执行阶段 A（AOT 完备），
> 阶段 B/C/D 是架构预留方向（每个架构决策须自问"JIT 时代还能工作吗"）。

## 阶段 A：AOT 完备（当前至 M8，主战场）

目标：封闭世界下用户代码全部静态可达，运行正确 + 性能 >= 官方 JIT（铁律 2e）。

| 里程碑 | 关键交付物 | 验收标准 |
|---|---|---|
| M4 并行扩展收尾 | pinvokeext 域（UTF-8 marshal/回调注册表）；异常边界；四态产物完整（SO 形态） | capi 四态测试；双跑一致 |
| M5 并行域（插入） | **属性折叠落地**（属性折叠设计.md：AccessorAnalyzer 预扫描 + StackFold.EmitCall 折叠）；阶段 1 转译器优化（性能路线图.md） | 反汇编无 accessor 调用；双跑一致；零警告 |
| M5 | BCL 全量转译（L1 裁剪默认，24 子代理并行，铁律 2k）；icall 表注册化（jit-预留.md #9）；类型注册表扩容（#11）；InternalCall 全枚举实现 | BCL 程序集可运行；e2e 矩阵扩大；CI 全绿 |
| M5.5 | 裁剪分级验证（L0/L1/L2 行为一致双跑） | 裁剪开关双跑一致 |
| M6 | 测试套件全绿对齐 + 三编译器 CI 常态化 + **基准体系起步**（性能路线图.md 阶段 4 最小骨架） | 测试全绿；基准基线入库 |
| M6.5 | DLR（CallSite + 自定义绑定器，零 Emit） | dynamic 用例双跑一致 |
| M7 | 解释器兜底（元数据 + IL 字节码执行，iOS 合规，非 JIT） | 动态入口（分析不到的泛型实参组合/运行时字符串类型名）用例正确 |
| M8 | 完整 CLDR / COM 互操作（远期） | 全球化/COM 用例 |

**AOT 完备门（阶段 A 出口判据）**：
① 裁剪 + 反射（元数据静态固化 + 统一 Invoker，铁律 2g-2）全链路可用；
② 泛型预实例化清单（编译期封闭世界分析）覆盖动态入口；
③ 解释器兜底运行分析不到的动态场景；
④ 性能基准：AOT 产物 >= net48 官方 JIT（铁律 2e 判据）。
此时用户程序"编译期可预见的一切"全部工作——这是"用户动态编程"的地基。

## 阶段 B：元数据运行时化（JIT 前置，架构准备）

目标：把"转译器 C# 侧独占的元数据"变成"运行时 C++ 侧可解析的数据"。
没有这一步，JIT 编译器在运行时拿不到签名/IL/方法表，无从编译。

| 交付物 | 内容 | 关联审计项 |
|---|---|---|
| 元数据静态固化 | 转译器把全量类型/方法/字段/特性/签名/IL 引用/字符串池序列化为紧凑二进制 static const 数组，内嵌只读段（铁律 2d/2j 既有设计哲学，memory.md 记录） | jit-预留.md #10 |
| 运行时方法描述符表 | `Il2CppClass` 尾部追加 `methods`/`methodCount`（方法名 + 签名编码 + fnPtr + IL 引用） | jit-预留.md #10/#8 |
| 通用方法表 | 全局/每类型方法 fnPtr 登记 API（`il2cpp_method_register`），导出表并入 | jit-预留.md #7/#8 |
| icall 注册表 | 运行时表 + 生成绑定代码（转译器特判 → 查表） | jit-预留.md #9 |
| 统一 Invoker ABI | 方法句柄 + 参数数组 marshalling（反射与 JIT 共用） | jit-预留.md #13/#15 |
| 反射元数据查询 | typeof/GetType/GetMethod/Invoke/特性查询全链路 | jit-预留.md #14 |
| 动态类型描述符构造 | 运行时构造 Il2CppClass（固定池分配）+ 注册；refFieldBitmap 运行时计算 | jit-预留.md #12/#11 |

验收：反射 e2e（Invoke/SetValue 行为一致）；元数据表三编译器零警告；
方法表查得到全部（或保留清单内）方法；GC 对运行时构造类型扫描正确。

## 阶段 C：代码生成器 JIT 化（核心 JIT 工程）

目标：把转译器的 IR（StackFold 产物）在**运行时**编译成原生机器码。

| 交付物 | 内容 |
|---|---|
| IR 抽象层 | 把"StackFold IR → 目标代码"拆为两后端：AOT 后端（现 C++ 发射，CodeGenerator）+ JIT 后端（x64 机器码发射）。IR 定义共用（Stmt/Expr 已是平台中立表达式树） |
| 自研 x64 后端 | 最小机器码发射器（覆盖 IR 子集：整数算术/比较/分支/字段访问/调用/返回；先值类型后引用），自研不依赖外部库（铁律：零第三方） |
| 方法表接入 | JIT 编译产物注册进方法表槽位；vtable/接口/委托槽位可指向 JIT 产物（ABI 一致，jit-预留.md #4/#5/#6） |
| 调用点策略 | AOT 直接调用保持符号调用（性能，铁律 2e）；JIT 方法调用点走方法表间接调用或 trampoline 回填（jit-预留.md 2.4） |
| 与解释器（M7）关系 | 解释器是 M7 的 iOS 合规执行路径；JIT 与解释器共享元数据表；桌面/服务器默认 JIT，移动端默认解释器（铁律 13） |
| 帧栈三合一 | JIT 方法序言/尾声调用同一 framestack 协议（已具备 API，jit-预留.md #20） |

验收：动态编译的委托/方法调用结果与 AOT 等价（双跑一致）；
JIT 编译热点方法性能 >= 解释器数量级；GC 压力下动态对象无泄漏。

---

## 阶段 D：动态加载（用户动态编程终态）

目标：用户程序运行时"写代码并执行"——编译期封闭世界被打破。

| 交付物 | 内容 |
|---|---|
| 运行时代码入口 | 用户 API（如 `IlcCompile(source)` / 委托式动态方法）→ 词法/语法/IL 生成（或直收 IL）→ 阶段 C 的 JIT 后端 |
| 动态类型全链路 | 运行时构造类型描述符 + 字段布局 + refFieldBitmap + 注册（阶段 B 已备）→ newobj/字段访问/isinst 全部可作用于动态类型 |
| 动态 icall/元数据 | 阶段 B 的 icall 表 + 元数据表是 JIT 生成代码的解析依据（不再有转译器特判） |
| 资源管理 | 动态代码/类型生命周期：可卸载域（JIT 产物回收、描述符池回收）——**设计预留，不默认支持多 AppDomain 语义** |
| 平台策略 | 桌面/服务器：完整 JIT；iOS：拒绝动态代码生成路径（编译期拦截），动态场景走解释器（铁律 13） |

验收：用户运行时生成的方法被调用、可反射、可被 GC 正确管理；
动态类型与 AOT 类型互操作（字段/虚调用/接口）；卸载后资源零残留。

## 依赖链与风险

```
阶段 A（AOT 完备）→ 阶段 B（元数据运行时化）→ 阶段 C（JIT 化）→ 阶段 D（动态加载）
   ↑ 当前执行            ↑ 需 A 的裁剪/反射闭环       ↑ 需 B 的表/ABI         ↑ 需 C 的编译器
```

| 风险 | 缓解 |
|---|---|
| iOS 政策与 JIT 冲突（铁律 13 vs 2j） | JIT 定位为桌面/服务器形态；移动端解释器兜底（M7）——解释器与 JIT 共享元数据，不重复建设 |
| 方法表化损害 AOT 性能（铁律 2e） | 直接调用保留符号调用；方法表只覆盖动态入口 + 导出（jit-预留.md 2.4 调用点策略） |
| 元数据体积爆炸（BCL 全量） | L1 裁剪默认 + 紧凑二进制编码（阶段 B 设计时就定编码器） |
| "禁内联"（帧记录铁律）与性能张力 | 属性折叠 = 合法内联替代（属性折叠设计.md）；AggressiveInlining 研究项带证明再实施（性能路线图.md 阶段 3） |
| 动态类型与精确 GC | refFieldBitmap 运行时计算（阶段 B 交付物）——GC 只读描述符，扫描路径零改动 |

## 每阶段自问（铁律 2j 边界检查）

- 阶段 A：新代码是否堵死"方法可替换/描述符可扩展/分配走分配器/元数据可达"？
- 阶段 B：表结构是否与 AOT 生成代码 ABI 一致？是否只增不改？
- 阶段 C：JIT 后端是否复用阶段 A/B 的 IR 与元数据，而非另起炉灶？
- 阶段 D：动态代码是否被 iOS 编译期拦截（编译期否决路径）？
